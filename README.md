# Рядом — сервис заказа поездок (WebToApp)

Полнофункциональный сервис заказа поездок с тремя ролями: **Заказчик**, **Исполнитель (водитель)** и **Администратор**. Мобильно-адаптивное PWA-приложение, готовое к упаковке в Android APK (WebToApp).

## Стек

| Слой | Технологии |
|---|---|
| Frontend | React 19, Tailwind CSS, shadcn/ui, lucide-react, sonner |
| Backend | FastAPI (Python), JWT-авторизация |
| База данных | MongoDB |
| Карты | Яндекс.Карты (JS API + геокодер), OSM Overpass (заправки) |
| Уведомления | OneSignal (push), SMS.ru (SMS + верификация звонком), SMTP (email админу) |
| Реалтайм | HTTP-polling (работает через любые прокси/файрволы) |

## Основные возможности

### Заказчик
- Регистрация по номеру телефона с подтверждением **звонком** (SMS.ru callcheck) + PIN-код для входа
- Создание заказа: адрес (текстом или тапом по карте), необязательное уточнение
- Поиск исполнителя в реальном времени, экран «Исполнитель найден» с ETA и звонком водителю
- Живое отслеживание машины на карте, звуковые уведомления (найден / завершено)
- История заказов, «Сообщить о проблеме», автоотмена заказа без исполнителя

### Исполнитель
- Регистрация: телефон → подтверждение звонком → анкета (имя, авто, номер) → активация админом
- Режим «На линии» / «С линии», список активных заявок со звуковым сигналом о новых
- Принятие заказа с выбором ETA, завершение поездки, баланс поездок
- Heartbeat-присутствие: в статистике «онлайн» только реально активные водители (120 сек)

### Админ-панель (`/admin`)
- Обзор, живая карта водителей, управление пользователями (активация, блокировка, удаление, баланс)
- Заказы, устройства, логи, системные логи (включая ошибки браузеров пользователей)
- **Тексты**: ~40 надписей приложения редактируются без программиста
- **Уведомления**: канал по умолчанию (Push / SMS / Push+SMS), события для SMS-дублирования, тест push/SMS, проверка подписки каждого пользователя
- **Настройки**: брендинг (название, иконка, SEO description), API-ключи (Яндекс, SMS.ru, OneSignal, SMTP), слайды на экране входа, режим обслуживания, тестовый режим, автоотмена заказов, подсказки адреса
- **Fab-бар**: настраиваемые кнопки нижнего меню + главная кнопка «Поездки»
- **Обновления**: загрузка ZIP-модулей

## Ключевые API

- `POST /api/auth/callcheck/start|status` — верификация звонком
- `POST /api/auth/complete-driver-profile` — анкета водителя после верификации
- `POST /api/orders/create`, `GET /api/orders/active|my-active`, `POST /api/orders/accept/{id}|complete/{id}`
- `GET /api/settings/public` — публичные настройки (брендинг, тексты, ключи карт)
- `POST /api/logs/client` — приём ошибок браузера
- `GET /api/manifest.json` — динамический PWA-манифест

## Как меняется брендинг/SEO

- **Название приложения** (Настройки → Брендинг) — шапка приложения, PWA-манифест и Title страницы (если SEO-заголовок пуст)
- **SEO: Заголовок / Описание** — `<title>` и `<meta name="description">`; при сохранении бэкенд патчит статический `index.html` (в опубликованной версии видно сразу в исходном коде страницы; в превью — после перезапуска фронтенда). Вкладка браузера обновляется сразу.

## Уведомления

1. **Push (OneSignal)** — бесплатно, работает и в свёрнутом приложении. Пользователь должен разрешить уведомления (пункт меню «Уведомления» показывает статус и подписывает).
2. **SMS (SMS.ru)** — платно, включается для выбранных событий или как канал по умолчанию.
3. **Внутренние звуковые** — пока приложение открыто: сигнал новой заявки у водителя, «исполнитель найден» у заказчика.

## Запуск (dev)

Сервисы управляются supervisor: `sudo supervisorctl restart backend|frontend`.
Backend: `0.0.0.0:8001` (все роуты с префиксом `/api`), Frontend: `:3000`.
Тестовый режим (Настройки → Режимы) — SMS-код `1234`, звонковая верификация подтверждается кнопкой, SMS уходят с флагом `test=1` (без списаний).
